## 1. Summary

Rewrite the `ffs grep` and `ffs multi-grep` CLI commands to stop doing their own `std::fs::read` + `Matcher` self-scan and instead search through `FilePicker::grep()` / `FilePicker::multi_grep()`, which already returns `GrepMatch.match_byte_offsets: SmallVec<[(u32,u32);4]>` for free — no re-search ever. Add a new termcolor-based renderer (first ANSI in the binary today, confirmed: zero `IsTerminal`/`NO_COLOR`/`\x1b` in `crates/ffs-cli/src`) that colors match=red+bold, path=magenta, line=green, gated on stdout-IsTerminal AND `NO_COLOR` AND `OutputFormat::Json` at a single choke point in `emit()`, so piped text and `--format json` stay byte-clean. Give `ffs find` fuzzy results color by switching from `match_list_parallel` (returns `Match`, no positions) to `match_list_indices` (returns `MatchIndices.indices`). Keep the JSON surface compatible: `path`/`line`/`text` unchanged, add optional `match_ranges`, bump `schema` to `"v1_ranges"`.

## 2. Target architecture

```
ffs grep / multi-grep
   │  args.needle / args.patterns (+ flags)
   ▼
FilePicker::new(FilePickerOptions { base_path: root, watch: false, ..Default::default() })
   │  picker.collect_files()  ── synchronous scan, no watcher, no lock needed
   ▼
parse_grep_query(&needle) ──→ FfsQuery                                [grep]
   │  has_regex_metacharacters(&parsed.grep_text()) → GrepMode::Regex | PlainText
   ▼
picker.grep(&parsed, &GrepSearchOptions{ mode, smart_case, max_matches_per_file, page_limit, .. })
   │  ── returns GrepResult { matches: Vec<GrepMatch>, files: Vec<&FileItem>, next_file_offset, … }
   ▼  (owned Strings copied out BEFORE picker drops)
GrepHit { path: relative_path(picker), line, text: line_content,
          match_ranges: Vec<{start,end}>, matched_patterns? }   [dedup / sort / truncate preserved]
   ▼
super::emit(format, &payload, render_text)        ←─ the ONE color gate
   │   Json  ──→ serde_json (no ANSI, ever)
   │   Text  ──→ if tty && !NO_COLOR → termcolor ANSI, else plain print!
   ▼
stdout

find: fuzzy_search_matches → match_list_indices → MatchIndices { indices: Vec<usize> }
      → sort_unstable() → byte-range runs → colored runs → same emit() gate
```

### 3.4 `crates/ffs-cli/src/commands/mod.rs` — the color gate
Replace `emit()` (lines 43-57) so the color decision lives in ONE place:

```rust
pub(crate) fn emit<T, R>(format: OutputFormat, payload: &T, render_text: R) -> Result<()>
where T: Serialize, R: FnOnce(&T) -> String {
    match format {
        OutputFormat::Json => println!("{}", serde_json::to_string_pretty(payload)?), // never ANSI
        OutputFormat::Text => {
            let color = std::io::stdout().is_terminal() && std::env::var_os("NO_COLOR").is_none();
            if color {
                print!("{}", render_text(payload));
            } else {
                print!("{}", strip_ansi(&render_text(payload)));
            }
        }
    }
    Ok(())
}
```

Contract: render closures ALWAYS build the string (ANSI or not); `emit()` strips on non-tty/NO_COLOR. One bypass: `find.rs:394-407` `--scored` branch does its own `println!` (ANSI-free; leave it, comment it must stay plain).

### 3.5 NEW `crates/ffs-cli/src/commands/render.rs`
Add `pub mod render;` to `mod.rs`. Contents:
- `highlight_ranges(text, ranges, spec, buf: &mut dyn WriteColor)` — cursor-walk; per range `set_color(spec)` + byte slice + `reset()` + gap. Byte slicing is valid UTF-8 (offsets are into lossy-but-UTF-8 `line_content`); clamp to `text.len()`; handle overlapping/adjacent ranges (advance to max end).
- `colorize_matches(text, ranges) -> String` — convenience (used by render closures; emit strips if non-tty).
- `colorize_substrings(text, byte_spans) -> String` — for find's fuzzy indices.

  - line number: `set_fg(Green)`
  - match: `set_fg(Red).set_bold(true)`
- Windows: termcolor's `StandardStream::stdout(ColorChoice::Auto)` handles VT enablement. Do NOT hand-roll `\x1b` + `SetConsoleMode`.

New `run()`:
```rust
let mut picker = ffs_search::FilePicker::new(FilePickerOptions {
    base_path: root.to_string_lossy().into_owned(),
    watch: false,
    ..Default::default()
})?;
picker.collect_files()?;

let q = ffs_search::parse_grep_query(&args.needle);   // or via grep module
let grep_text = q.grep_text();
let mut use_regex = args.regex || (!args.fixed_strings && has_regex_metacharacters(&grep_text));
let mut final_text = grep_text.clone();
if args.word_regexp && use_regex { final_text = format!(r"\b(?:{final_text})\b"); }
let q = ffs_search::parse_grep_query(&final_text);      // rebuild so constraints intact

let smart_case_sensitive = args.case_sensitive || args.needle.chars().any(|c| c.is_uppercase());
let mode = if use_regex { GrepMode::Regex } else { GrepMode::PlainText };

let options = GrepSearchOptions {
    max_file_size: 10 * 1024 * 1024,
    max_matches_per_file: if args.files_with_matches { 1 } else { args.max_count }, // 0 = unlimited
    smart_case: !smart_case_sensitive,
    file_offset: 0,
    page_limit: args.limit.max(1),
    mode,
    time_budget_ms: 0,
    before_context: 0, after_context: 0,
    classify_definitions: false,
    trim_whitespace: false,
    abort_signal: None,
};
let result = picker.grep(&q, &options);

if let Some(err) = &result.regex_fallback_error { eprintln!("ffs grep: warning: fell back to literal: {err}"); }

// COPY OUT owned data BEFORE picker drops (GrepResult borrows &FileItem)
let mut hits: Vec<GrepHit> = Vec::new();
for m in &result.matches {
    let file = result.files[m.file_index];
    hits.push(GrepHit {
        path: file.relative_path(&picker),
        line: m.line_number as u32,
        text: m.line_content.clone(),
        match_ranges: m.match_byte_offsets.iter().map(|&(s,e)| MatchRange{start:s, end:e}).collect(),
    });
}
// Dedup by line per file (engine does NOT dedup) — keyed on (path, line), keep first
// sort (path, line), truncate(limit), -l transform — replicate current behavior
// --group → build_grouped_result(&args.needle, &hits, mode_str)
```

## 5. JSON schema

Compatibility: keep `path`/`line`/`text` byte-for-byte; add `match_ranges` optional (skipped when empty); bump `schema`. Range shape = C-ABI `FfsMatchRange { start: u32, end: u32 }` (byte offsets `[start, end)` into `text`).

```jsonc
// ffs grep --format json (schema "v1_ranges")
{
  "needle": "foo",
  "hits": [
    {
      "path": "crates/ffs-cli/src/main.rs",      // STABLE
      "line": 42,                                 // STABLE (u32, 1-based)
      "text": "let foo = bar;",                   // STABLE
      "match_ranges": [ { "start": 4, "end": 7 } ] // NEW, skipped when empty
    }
  ],
  "total_files_searched": 1280,
  "mode": "literal",
  "schema": "v1_ranges"
}

// ffs multi-grep (schema "v1_ranges")
{ "patterns": ["TODO","FIXME"], "hits": [ { "path": "...", "line": 7, "text": "// TODO: fix",
    "match_ranges": [ { "start": 3, "end": 7 } ],
    "matched_patterns": ["TODO"] } ],
  "total_files_searched": 1280, "mode": "multi-literal-or", "schema": "v1_ranges" }
```

- `trim_whitespace: false` → ranges/text relative to RAW line (C-ABI-consistent). MCP uses `true` — surfaces differ; document.
- Grouped JSON (`v2_grouped`) unchanged (`{line, text}` only); optionally add `match_ranges` later.
- Do NOT add `col`/`byte_offset`/a `match_byte_offsets` key — canonical name is `match_ranges`.

## 9. Risks & open questions (need owner sign-off)

1. **No on-disk bigram index in `collect_files()`** (verified `file_picker.rs:2196` `bigram_index: None`). CLI today pre-filters via `CacheDir::load_bigram_index`. After switch, literal grep does a full scan per invocation. **OVERRIDDEN — NOT acceptable as-is.** Bigram prefilter phải được giữ. Option: wire `set_bigram_index` sau khi load disk cache (cache.rs `CacheDir::load_bigram_index`), hoặc giữ CLI self-scan + bigram nếu engine không chứng minh được speedup. Merge gate = benchmark.
2. **Root/index cost**: `collect_files()` is a full synchronous walk (git-status-aware) — same order as current `walk_files` + engine overhead. Benchmark to confirm.
3. **`page_limit` is soft/file-granular** (`page_limit + max_matches_per_file - 1` possible) — MUST `hits.truncate(limit)` post-engine. Engine `max_matches_per_file: 0` = unlimited; don't map 0→usize::MAX.
4. **`matched_patterns` reconstruction**: engine returns ranges, not which pattern. Re-match per-pattern against `line_content` (≤512B, cheap). Smart-case rule maps cleanly: engine single `smart_case = !patterns.iter().any(uppercase)` — exactly current rule.
5. **`total_files_searched` semantics** (bug-18 full-walk → engine consumed-files): DECIDE (a) accept engine count, or (b) full-walk on no-match path. Recommend (a).
6. **Regex auto-detect divergence** (10 vs 18 chars): RECOMMEND adopt engine `has_regex_metacharacters(&parsed.grep_text())` (MCP parity). Changes `ffs grep 'foo-bar'` from literal→regex. Update/delete `looks_like_regex` test.
7. **Invalid-regex exit**: RECOMMEND hard error on explicit `-r`/`--regex`; eprintln warning + continue on auto-detect fallback.
8. **`-w` whole-word**: wrap `grep_text` BEFORE `parse_grep_query`; literal `-w` stays no-op (current behavior).
9. **`--group` survives**: needs `path`/`line`/`text` — present. `line_number` u64 → u32 safe.
10. **Find fuzzy perf**: `match_list_indices` documented "not optimized", single-threaded. Mitigation: `match_list_parallel` for ranking, `match_list_indices` only on top-N accepted set.
11. **GrepResult borrow**: `result.files` borrows picker. CLI owns `FilePicker` directly (single-threaded OK — NOT Sync but used on main thread). Copy `relative_path` before `picker`/`result` drop.
12. **Windows path separator / path absolute-vs-relative**: engine emits RELATIVE paths via `relative_path()`; current CLI emits absolute lossy. REAL compat break for JSON consumers. DECIDE: emit relative (MCP-style) or reconstruct absolute via `base_path.join(relative)`. Default: relative, documented loudly.
13. **`trim_whitespace: false`** for CLI (raw line + ranges) vs MCP `true` — surfaces differ; document.
14. **`has_regex_metacharacters` needs `grep_text()`** (constraint-stripped), not raw needle — per MCP `server.rs:802-806`.

## ✅ Task #3 — Regex vs PlainText benchmark (release, ffs repo 618 files, warm bigram)

> Đo gap giữa 2 matcher của CLI: **literal (memmem SIMD)** vs **regex (`regex::bytes::Regex` trên toàn buffer, không candidate-line prefilter)** — `bench_grep --compare-regex`. Same needle, so sánh công bằng.

| Needle | literal(memmem) | regex | regex/literal |
|---|---|---|---|
| `FilePicker` | 10.8 ms | 27.3 ms | **2.5x** |
| `grep_search` | 7.6 ms | 29.9 ms | **3.9x** |
| `TODO` | 12.2 ms | 26.7 ms | **2.2x** |
| `match_byte_offsets` | 5.9 ms | 93.2 ms | **15.7x** |
| `HashMap` | 4.8 ms | 29.9 ms | **6.3x** |
| `fn\s+\w+\(` (regex-only) | — | 41.0 ms | **26.5x** |
| `File\w+` (regex-only) | — | 72.3 ms | **45.9x** |
| `TODO\|FIXME` (regex-only) | — | 33.9 ms | **19.4x** |
| `\bHashMap\b` (regex-only) | — | 30.2 ms | **20.5x** |

**Kết luận:**
- Literal-mode needle: regex chậm hơn **2–16x**.
- Pattern bắt buộc phải regex (metachar): regex chậm hơn **19–46x** — regex engine quét toàn buffer, không prefilter candidate line.
- **Đây chính là gap mà literal prefilter (rg-style `find_candidate_line`) có thể đóng**: extract required literal → memmem scan trước → chạy regex thật chỉ trên dòng ứng viên. Tiềm năng speedup lớn nhất còn lại.
- **Phân bổ thời gian**: regex 27–93ms vs literal 5–12ms. Trong đó phần lớn là regex engine chạy trên từng file mà không có prefilter.

> **Ghi chú:** gap này nằm ở **CLI self-scan** (hiện đã giữ nguyên sau Track B). Một prefilter literal cho Regex mode là công việc tương lai độc lập (không phải engine switch) — tham chiếu `docs/RIPGREP_STUDY.md` §2 cho hướng `find_candidate_line`.

> **KẾT LUẬN: GIỮ CLI SELF-SCAN. KHÔNG chuyển sang engine.**

- **Warm bigram (trạng thái bình thường sau `ffs index`)**: CLI self-scan nhanh hơn engine **3–7x**. Bigram prefilter là lợi thế quyết định — đúng như owner dự đoán khi override §9.1.
- **Cold cache**: engine nhanh hơn 1.4x — nhưng đó là trạng thái tạm (chỉ khi `.ffs` thiếu/stale), không phải steady-state.
- Engine `enable_content_indexing` (engine+index) **không giúp** — bigram build cost nằm trong mỗi lần `collect_files` một-shot, không phải lợi thế prefilter dùng lại như CLI cache.

**Merge gate owner: `new ≤ old` KHÔNG đạt (engine chậm hơn 3-7x). → Track B dừng ở đây. Không engine switch. Không xoá bigram.**

Đây chính là regression mà owner cảnh báo khi override §9.1 ("Accept" sai). Plan gốc đã được sửa thành benchmark-first; benchmark chứng minh quyết định đúng là **giữ CLI self-scan**.
