## The Big Idea

ffs-mcp isn't just a "search wrapper" — it's the foundation for a new class of
AI developer tools where search IS the interface.

### Core Insight: Replace Navigation with Semantic Search

Traditional developer tools: navigate → find → read → understand
ffs-mcp approach: ask → find → understand

The fundamental shift: instead of asking developers to know WHERE something is
and navigate a file tree, they describe WHAT they want and the system finds it.

### What's New (Beyond Traditional Code Search)

1. Fuzzy Natural Language
   - "find error handling patterns" → finds match!, handle!, unwrap_or, etc.
   - "authentication middleware" → finds auth guards, JWT validation, session checks
   - No need to know exact function names or file paths

2. AI-Powered Understanding
   - Results include semantic context, not just line numbers
   - The AI agent explains WHY a result matches, not just THAT it matches
   - Connected concepts: "rate limiting" → limiter.rs + middleware.rs + config.yaml

3. Live System Status
   - "is ffs-mcp running?" → healthy, uptime, memory, DB size
   - "show search performance" → search stats, avg latency, cache hit rate
   - "how many files are indexed?" → 1,847 files, 2.3 MB index

4. Cross-Format Understanding
   - Same query works across .rs, .ts, .py, .js, .json, .yaml, .toml, .md
   - "find configuration" matches settings.rs, config.yaml, .env.example, etc.
   - Auto-detects language and applies appropriate strategies

5. Natural Conversations About Code
   - "why is this function slow?" → profile + grep + deps analysis
   - "how does auth work here?" → architectural walkthrough
   - "what changed in the last week?" → git log + file summary

### The "10x Developer Experience" Moments

1. Instant Code Exploration

   After: "how does the cache layer work?" → instant architectural overview

## System Architecture Overview

ffs-mcp is an MCP server that provides tools for code intelligence. It runs as
a background process and communicates with AI agents via the Model Context
Protocol (MCP). The server indexes codebases and provides fast search, analysis,
and navigation capabilities.

## Tool Implementation Details

### ffs_dispatch: Query Classification

Routes natural language queries to the appropriate tool:

  Query patterns:
  - "function X", "struct X", "fn X", "class X"  → ffs_symbol
  - "X calls", "callers of X", "who calls X"      → ffs_callers
  - "X callees", "what does X call", "X uses"     → ffs_callees
  - "deps of X", "imports in X", "dependents"     → ffs_deps
  - "find X", "search X", "where is X"            → ffs_grep
  - "overview", "summary", "project"              → ffs_overview
  - "tree", "structure", "map"                    → ffs_map
  - "outline of X", "structure of X"             → ffs_outline
  - "impact of X", "what breaks if X changes"    → ffs_impact
  - "related to X", "refs to X"                  → ffs_refs
  - "X siblings", "peers of X"                   → ffs_siblings

### ffs_outline: File Structure

Returns the structural outline of a file (functions, classes, modules):

  Input:  { "path": "src/lib.rs" }
  Output:
    - Functions: main(), helper(), parse_input()
    - Structs: Config, AppState
    - Enums: Error, Command
    - Modules: mod utils, mod parser
    - Line numbers for each definition

### ffs_symbol: Symbol Lookup

Finds all definitions of a symbol across the workspace:

  Input:  { "name": "Config", "maxResults": 10 }
  Output:
    - Definitions with file path, line number, kind
    - The actual code snippet
    - Language (Rust, TypeScript, etc.)

### ffs_callers: Who Calls This?

Finds all call sites of a function/method:

  Input:  { "name": "parse_input", "maxResults": 20 }
  Output:
    - Call sites: main.rs:42 calls parse_input()
    - Call sites: cli.rs:18 calls parse_input()
    - Context snippet around each call

### ffs_callees: What Does This Call?

Lists symbols referenced inside a function body:

  Input:  { "name": "run_server", "maxResults": 20 }
  Output:
    - Callees: Config::load(), Router::new(), listen()
    - Direct dependencies of this function

### ffs_deps: File Dependencies

Shows imports + workspace files that depend on a file:

  Input:  { "path": "src/config.rs" }
  Output:
    - Imports: use crate::utils; use std::fs;
    - Dependents: main.rs, server.rs, cli.rs

### ffs_impact: Change Impact Analysis

Ranks files by how much they'd be affected if a symbol changed:

  Input:  { "name": "Config", "maxResults": 10 }
  Output:
    - High impact: config_loader.rs (directly uses Config)
    - Medium impact: server.rs (uses Config through ConfigLoader)
    - Low impact: main.rs (passes Config as parameter)

### ffs_grep: Content Search

Searches file contents with regex or fuzzy matching:

  Input:  { "query": "rate_limit", "maxResults": 50 }
  Output:
    - Matches: api/handler.rs:45: rate_limit(100)
    - Matches: middleware/limiter.rs:12: struct RateLimiter
    - Context lines around each match

### ffs_multi_grep: Multi-Pattern Search (Aho-Corasick)

OR-logic search for multiple patterns simultaneously:

  Input:  { "patterns": ["TODO", "FIXME", "HACK"], "limit": 100 }
  Output:
    - All matches from all patterns in one pass
    - Pattern label for each match

### ffs_find: Fuzzy File Search

Finds files by fuzzy name matching:

  Input:  { "query": "config", "maxResults": 10 }
  Output:
    - src/config.rs
    - config/default.yaml
    - .env.example

### ffs_map: Project Tree

Shows directory structure with file counts and token estimates:

  Input:  { "depth": 3 }
  Output:
    - Tree visualization with file counts per directory
    - Estimated token count for each directory

### ffs_overview: Project Summary

High-level overview of the codebase:

  Input:  (none)
  Output:
    - Languages used (Rust: 80%, TypeScript: 15%, Python: 5%)
    - Top-defined symbols
    - Entry points (main(), index.ts, etc.)
    - Key modules and their responsibilities

### ffs_refs: Symbol References

Shows definitions plus single-hop usages of a symbol:

  Input:  { "name": "AppState" }
  Output:
    - Definition: server.rs:25 struct AppState
    - Used in: handler.rs:12 (parameter), cli.rs:45 (constructed)


## Data Flow: How a Query Gets Processed

User: "how does authentication work?"

1. Query arrives via MCP (JSON-RPC 2.0)
2. ffs_dispatch classifies query → multiple tools needed
3. Parallel execution:
   - ffs_grep(query="auth|authenticate|middleware|guard") → file matches
   - ffs_symbol(name="auth") → symbol definitions
   - ffs_callers(name="authenticate") → call sites
4. Results formatted into structured response
5. Response returned to AI agent
6. Agent synthesizes findings into human-readable answer
7. Agent provides architectural explanation to user


## State Management

Server maintains in-memory state:

  - File index: HashMap<PathBuf, FileMetadata>
  - Symbol index: HashMap<String, Vec<SymbolDef>>
  - Call graph: HashMap<String, Vec<String>> (callers/callees)
  - Content cache: HashMap<PathBuf, String> (file contents)
  - Git metadata: last commit, branch, dirty status

Index is rebuilt on startup and refreshed periodically or on explicit request.


## Communication Protocol

Uses MCP (Model Context Protocol) over JSON-RPC 2.0:

  Transport options:
  - Stdio: for local CLI integration
  - SSE (Server-Sent Events): for remote/network access
  - WebSocket: for bidirectional streaming (future)

  Message format:
  {
    "jsonrpc": "2.0",
    "method": "tools/call",
    "params": {
      "name": "ffs_grep",
      "arguments": { "query": "auth", "maxResults": 20 }
    },
    "id": 1
  }


## Performance Characteristics

  - File walk: ~50ms for 1,000 files
  - Symbol indexing: ~200ms per 1,000 functions
  - Content search (grep): ~10ms per 1,000 files
  - Symbol lookup: ~5ms (hash map)
  - Call graph traversal: ~10ms per hop
  - Total query time: typically < 100ms

  Index size: ~100KB per 1,000 files
  Memory usage: ~50MB for 10,000 file project


## Integration Points

  ffs-mcp integrates with:
  - ffs-core: core search engine and indexing
  - ffs-cli: command-line interface (same engine)
  - tree-sitter: AST parsing for symbol extraction
  - git2: Git history access
  - sqlite: Persistent index storage
  - serde_json: MCP protocol serialization
